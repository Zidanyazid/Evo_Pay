API RELIABILITY

Usage limits per Site

Setiap Site dibatasi per fixed window 60 detik: create payment 30/minute dan sync 60/minute secara default. Admin dapat mengubah limit per Site dari dashboard.

Saat limit habis, response 429 RATE_LIMITED menyertakan Retry-After, X-RateLimit-Limit, X-RateLimit-Remaining, dan X-RateLimit-Reset. Gunakan backoff; jangan melakukan retry loop.

SITE OPERATIONS

Maintenance mode

Saat Site sedang deploy, admin dapat menghentikan pembuatan payment baru tanpa mematikan API key. Request create akan menerima 503 SITE_MAINTENANCE dengan header Retry-After: 300.

{
  "error": {
    "code": "SITE_MAINTENANCE",
    "message": "Pembayaran sementara tidak tersedia untuk Site ini.",
    "retry_after_seconds": 300
  }
}

Jangan loop request create. Tampilkan pesan lalu coba kembali setelah deploy. Get/sync payment existing dan webhook tetap berjalan.

PAYMENT LIFECYCLE

Payment expiration

Payment LIVE yang tetap PENDING setelah expires_at dari Tokopay akan ditandai EXPIRED oleh EvoPay. Selalu tangani status EXPIRED saat menampilkan checkout atau memeriksa order.

Payment tanpa expiry dan Site TEST tidak diproses. Expiry tidak memicu callback karena event EvoPay saat ini hanya payment.paid.

NODE.JS

Copyable client helper

Salin examples/node/evopay-client.js ke backend project Anda. Helper ini memakai native fetch, timeout, dan request ID.

import { EvoPayClient } from './evopay-client.js';
const pay = new EvoPayClient({
  baseUrl: process.env.EVOPAY_URL,
  apiKey: process.env.EVOPAY_API_KEY
});
const payment = await pay.createPayment({
  order_id: 'TOPUP-10001', amount: 15000, payment_method: 'QRIS'
});

PHP

Native cURL helper

Salin examples/php/evopay_client.php ke backend PHP Anda. Tidak perlu Composer atau package tambahan.

require 'evopay_client.php';
$pay = new EvoPayClient($_ENV['EVOPAY_URL'], $_ENV['EVOPAY_API_KEY']);
$payment = $pay->createPayment([
  'order_id' => 'TOPUP-10001', 'amount' => 15000, 'payment_method' => 'QRIS'
]);

OPERATIONS

Recovery & escalation

Simpan x-request-id untuk setiap error integrasi. Untuk 429, gunakan backoff mengikuti Retry-After; untuk 503 SITE_MAINTENANCE, tampilkan pesan sementara dan jangan retry loop; tangani EXPIRED sebagai checkout tidak lagi dapat dibayar.

Operator gateway dapat menggunakan Recovery Center dan Recovery Runbook untuk callback gagal, provider delay, database, backup, dan credential rotation.

ERROR HANDLING

Request ID

Setiap response public API menyertakan header x-request-id. Simpan ID ini bersama error integration agar pencarian Activity Log atau server log lebih cepat.

try { await pay.createPayment(input); }
catch (error) {
  console.error(error.status, error.code, error.requestId);
}

SANDBOX MODE

Site TEST tanpa Tokopay

Buat Site dengan environment TEST dari dashboard. Site TEST memiliki API key dan callback sendiri; create payment hanya memakai simulator EvoPay lokal, tidak membuat order maupun dana di Tokopay.

POST/api/v1/payments/:id/complete-test

Gunakan endpoint ini hanya dengan API key Site TEST untuk menandai payment test sebagai PAID dan memicu callback signed. Endpoint menolak payment LIVE.

WEBHOOK TEST

Test callback delivery

Pada Site aktif dengan callback URL, tekan Test webhook di dashboard. EvoPay mengirim event payment.paid sintetis dengan test: true, signature HMAC asli, dan header delivery ID unik.

{
  "event": "payment.paid",
  "test": true,
  "data": { "id": "test_...", "environment": "TEST", "amount": 1000 }
}

Test tidak membuat payment, tidak menghubungi Tokopay, dan tidak tercampur dengan callback payment asli. Handler harus melakukan deduplication memakai x-evopay-delivery. Satu test per Site setiap 60 detik.

WEBHOOK SECURITY

Verifikasi signature

Callback memiliki header x-evopay-signature: sha256=<digest>. Hitung HMAC SHA-256 dari raw request body menggunakan webhook secret Site Anda, lalu bandingkan dengan aman.

// Node.js
const expected = crypto
  .createHmac('sha256', process.env.EVOPAY_WEBHOOK_SECRET)
  .update(rawBody)
  .digest('hex');

const signature = req.headers['x-evopay-signature'];
const valid = crypto.timingSafeEqual(
  Buffer.from(`sha256=${expected}`),
  Buffer.from(signature)
);

WEBHOOK HANDLER

Handler examples

Gunakan raw request body untuk HMAC verification. Deduplicate berdasarkan header x-evopay-delivery sebelum memenuhi order.

Node.js

import { handlePaymentPaid } from './webhook-handler.js';
await handlePaymentPaid({ rawBody, signature, deliveryId, secret,
  hasProcessed, processPayment, markProcessed });

PHP

require 'webhook_handler.php';
$event = handle_payment_paid($rawBody, $signature,
  $deliveryId, $_ENV['EVOPAY_WEBHOOK_SECRET']);
